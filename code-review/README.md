# 循练 · 本地代码记忆工作台

独立于 `../sqlitwork` 的本地应用。用户提供模型 API 和自己的代码目录，工具自动审查已有代码及后续保存的变更，把代码快照、算法概述、问题和建议保存为可检索的记忆，再通过对话回顾自己的实现。

## 启动

需要 Node.js 24+，不需要安装 npm 依赖、JDK 或数据库服务。

```powershell
cd ./code-review
npm start
```

以上命令从项目父目录执行；已进入 `code-review` 时直接运行 `npm start`。也可双击 `启动.bat`。浏览器打开 <http://127.0.0.1:18081>。停止服务：在运行终端按 Ctrl+C。端口冲突时，可在 PowerShell 中先设置 `$env:PORT = '18082'`。

## 第一次使用

1. 打开“连接与设置”，填写自己的源码目录，例如 `../solutions`。相对路径以启动服务时的工作目录（通常为 `code-review/`）为基准，也支持用户自己机器上的绝对路径。
2. 填写 Chat Completions 兼容服务的 API 基础地址、模型名称、API Key。基础地址通常以 `/v1` 结尾；也支持填完整 `/chat/completions` 地址。远程服务必须使用 HTTPS，本机模型允许 HTTP。
3. 可先点“测试 API 连接”。勾选“保存代码后自动审查”，点击“保存并开始扫描”。首次扫描会审查目录内已有源码，会产生对应模型调用费用。
4. 在编辑器保存代码。工作台每 3 秒检查一次，连续两次读取内容一致后建立快照并审查，一般约 3～6 秒入队，模型生成时间另计。也可点“立即扫描”，立即索引并重试失败任务。
5. 查看“代码审查”和“代码沙盒”，或在“记忆对话”提问，例如“我写过哪些算法？”“binary.cpp 的二分边界有什么风险？”“根据这些代码安排下一步练习”。回答下面列出本次提供给模型的文件与行范围，可点击查看对应版本。

关闭自动审查后，仅保存设置或手动扫描时索引。服务需保持运行；重启后会继续检查变化。原文件删除后退出当前检索，旧报告和快照仍保留。同一路径的相同内容复用报告，不重复调用模型。切换目录后，文件、审查和聊天按目录分别保存。

API 调用出错或模型返回无效 JSON/行号时，显示失败并暂停审查队列，避免自动循环调用；修正设置后点击“立即扫描”重试。审查报告是模型观察，未进行编译、执行或在线判题。

## 文件夹沙盒和数据

这里的“沙盒”是**限定读取目录与独立快照存储**，不是用于执行不可信程序的操作系统沙盒。工具不执行源码，不修改源文件，也不给模型提供文件写入或命令执行工具。

```text
code-review/
├─ server.mjs                  本机 HTTP 服务
├─ src/
│  ├─ scanner.mjs              目录范围检查、源码扫描、内容哈希
│  ├─ model.mjs                模型协议、提示词与结果校验
│  └─ workspace.mjs            自动审查队列、SQLite 记忆、对话检索
├─ public/                     对话、审查、快照、设置页面
├─ test/                       自动化测试
└─ data/                       运行后生成，已被 .gitignore 排除
   ├─ settings.json            API 地址、模型、密钥和目录设置
   ├─ memory.sqlite            文件索引、版本审查报告、对话记录
   └─ sandboxes/<目录ID>/snapshots/<内容哈希>.txt
```

API Key 保存于本机配置文件，状态接口不会返回密钥，页面留空可保留旧值。快照保存完整的已索引源码，因此备份或共享 `data/` 时需要考虑代码及密钥内容。停止服务后可备份整个数据目录；删除该目录会清除工具的配置和记忆。该工具设计为单用户、本机使用，只监听 `127.0.0.1`，不提供多账号访问。

默认扫描 C/C++、Python、Java、JavaScript、TypeScript、Vue、Rust、Go、C#、Kotlin、SQL 等源码。跳过符号链接、隐藏目录、`.git`、`node_modules`、构建目录、`data`、常见密钥文件名和二进制内容。默认不解析 `.gitignore`；建议选择专门的练习目录。文件名过滤无法识别源码中硬编码的秘密，请先移除这些内容。

单个源码文件上限 96 KB，每个目录最多 2000 个源码文件、10 MB 内容、10000 个子目录。超限会明确显示。每次审查发送完整的当前文件和同文件的最近两份报告；对话采用路径、代码内容与报告的关键词检索，提供最多 6 个文件、每份约 6000 字符、总计约 32000 字符的代码片段。它不会一次读取并理解整个大型项目，不支持模型自主跨目录检索。

## 接口

| 接口 | 作用 |
| --- | --- |
| `GET /api/state` | 配置状态、当前索引、最近 100 份报告、最近 60 条聊天 |
| `POST /api/settings` | 保存 `root/baseUrl/model/apiKey/autoReview` 并开始扫描 |
| `POST /api/test` | 测试所填模型连接，不保存设置 |
| `POST /api/scan` | 立即扫描并重试失败审查 |
| `POST /api/chat` | 提交 `{ "message": "问题" }`，返回回答和检索来源 |
| `GET /api/source?path=...&hash=...` | 读取已登记的当前/历史代码快照 |

写接口只接受 JSON，限制 Host 和 Origin。源码文件内容和模型输出均按纯文本显示，防止把源码中的 HTML 当作页面执行。

## 测试

```powershell
npm test
```

测试使用临时目录和模拟模型，不需要个人 API Key，也不会审查个人代码。覆盖目录过滤、行号检查、保存后自动审查、哈希去重、失败暂停及重试、版本与目录隔离、持久化、对话来源和本机 HTTP 接口。真实服务商的兼容性、额度及模型审查质量需要在填写 API 后验证。

也可直接对自己的真实代码目录做离线验收，不配置或调用模型 API：

```powershell
node ./scripts/local-check.mjs ../solutions
```

离线验收检查实际目录的扫描、快照、重复版本去重、四组算法关键词检索以及行号对应关系，结果保存在 `./data/local-validation/report.md` 和 `result.json`。它不会生成模型回答，也不把索引成功当成代码正确。原始代码目录只读，验收快照使用独立数据目录。
