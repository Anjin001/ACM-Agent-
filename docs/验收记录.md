## 2026-11-12 本机复验

复验时修复两处启动阻塞：

1. `scripts/Tools.ps1` 的 JDK 探测原先只检查 `JAVA_HOME` 与 `C:\Program Files` 下的目录，JDK 装在 `E:\java\JDK 17` 时被误判为未安装。现增加 PATH 上的 `javac`/`java`、注册表 JavaHome，以及各盘符常见安装目录。
2. 端口原取自 `${PORT:18080}`，宿主环境存在 `PORT` 变量时会绑定到该端口（复验时为已被占用的 40334）并启动失败。现改用 `${XUNLIAN_PORT:18080}`，`Start.ps1` 启动前检查端口占用并显式传入 `--server.port`。

## 2026-11-12 扩展模块复验

同上环境。本次做了两件事：把存储层从 H2 换成 SQLite（保留 MySQL 作为可切换后端），并在其上补齐三个模块——自然语言处理、能力画像建模、教练记忆、本地代码审查。

### 存储层

数据库文件改为 `data/xunlian.db`，连接串 `jdbc:sqlite:./data/xunlian.db?journal_mode=WAL&busy_timeout=5000&foreign_keys=on`，连接池 4 条。启动时自动创建 `data` 目录。表结构从 4 张扩到 7 张，新增 `observations`（观察，带 `source_type`/`source_id` 出处与 `weight` 权重）、`training_events`（时间线）、`code_reviews`（审查记录，只存文件名、行数、字符数与结论，不存源码）。`observations` 上有 `(user_id, kind, statement)` 唯一索引，写入走 `ON CONFLICT ... DO UPDATE` 累加权重。MySQL 侧的等价 DDL 在 `schema-mysql.sql`，用 `DB_DRIVER`、`DB_SCHEMA` 切换。`MemoryStore` 只有一处方言差异（upsert），按驱动名在 `ON CONFLICT ... DO UPDATE` 与 `ON DUPLICATE KEY UPDATE` 之间选择，因此切换 MySQL 不需要改代码。集成测试也改用 SQLite 临时库（`target/test-<uuid>.db`），与生产同方言。

### 新增能力

| 模块 | 实现要点 |
| --- | --- |
| 中文时间意图（`Nlp.java`） | 不依赖第三方库，字典 + 正则。支持每天/隔天、只有周X有空、周X＋时长、周末、今天/明天/后天/大后天、整周否定；时长识别一个半/半小时/一刻钟/两刻钟/N小时/N分钟，中文数字含十、二十五与全角数字 |
| 归因抽取（`Nlp.java`） | 六类词表（边界/复杂度/审题/实现/算法/时间），按分句做否定作用域判断，程度副词加权：又/还是/总是/经常/老是/反复 记 1.6，有点/稍微/偶尔/一次 记 0.7 |
| 能力画像（`ProfileModeler.java`） | 按专题给 1～5 级，附样本数、独立完成率、用时偏差、证据链、100 分一档的难度分布。等级公式先算 `0.65×独立率 + 0.35×难度`，再乘置信度 `min(1, 0.4 + 0.2×样本数)`，避免 1 条样本就顶到 4 级 |
| 教练记忆（`MemoryStore` / `CoachMemory`） | 每条观察都有出处，可更正、可停用、可删除；计划生成与调整时把有效观察作为语境，输出的 `basis` 若不在记忆或画像里则被丢弃，防止模型编造依据 |
| 本地代码审查（`CodeReviewer.java`） | 规则引擎先跑，覆盖整数中点溢出、`memset` 作用于 `double`、`%d` 读 `long long`、`double` 直接判等、循环内 `endl`、`<=` 上界配下标、数组常量过小、`int` 累加、嵌套过深、未解除 `cin` 同步、`bits/stdc++.h`。单文件 2 万字符、单次 6 万字符、最多 5 个文件；未配置模型密钥或校验失败时 `engine` 保持 `rules` |
| 计划校准（`Planner.java`） | 按专题取 `实际用时/估时` 的中位数（至少 2 条样本，夹在 0.5～2.0），任务估时夹到 10～240 分钟，并在理由里说明校准依据 |
