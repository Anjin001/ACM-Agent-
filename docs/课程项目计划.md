# 循练课程项目计划草案

本计划按 4 人、6 周估算。成员姓名、课程截止日期、老师指定文档格式和实际成本待小组填写。当前代码为需求讨论与课堂演示的首版，需求访谈及真实用户试用需要由小组开展并保留原始记录。

## 项目目标与范围

用户输入训练目标、可用时间和 CF handle 后，获得可执行的周计划。训练反馈影响后续安排，用户能够查看原因、接受调整并撤销修改。

首版覆盖个人账号、CF 公开记录同步、跨平台精选题目录、周计划、训练复盘、规则调整与可配置的大模型调整。六周范围以个人训练流程为验收中心。

| W05 选题与排期 | C | 5 | 真实题目、已知完成题排除、时间预算 |
| W06 复盘与计划版本 | C、D | 5 | 反馈、方案确认、撤销保留训练记录 |

## 六周里程碑

| 周次 | 主要目标 | 可验收成果 |
| --- | --- | --- |
| 第 1 周 | 访谈、范围与数据验证 | 一页范围说明、访谈记录、CF 验证程序、页面原型 |
| 第 2 周 | 基础系统 | 保存设置、账号隔离、固定计划、持久化反馈 |
| 第 3 周 | 自动选题与周计划 | 按实际剩余日期排期，验证候选来源与时间预算 |
| 第 4 周 | 反馈驱动调整 | 调整前后对比、方案确认、版本撤销、真实模型配置 |
| 第 5 周 | 测试与真实试用 | 测试记录、问题修复、用户意见及对应变更 |
| 第 6 周 | 验收与答辩 | 可重复演示、数据来源说明、完整课程材料 |

## 风险与应对

| 风险 | 影响 | 处理及负责人 |
| --- | --- | --- |
| CF 限流或不可达 | 记录无法及时更新 | B 统一限流、显示同步状态，保留已有数据 |
| 洛谷历史记录接口待验证 | 自动同步工期不确定 | A 将首版验收确定为题目链接和手动反馈 |
| 模型调用失败或产生错误任务 | 计划不可执行 | C 校验候选和时间，回退规则方案 |
| 推荐题不适合用户 | 训练体验不佳 | C 收集复盘，D 整理试用意见并调整人工用时 |
| 需求持续增加 | 影响交付 | A 记录变更原因、预计工时、里程碑影响和处理决定 |
| 演示网络异常 | 现场流程中断 | D 准备明确标注来源的本地数据和演示空间 |

## 协作和跟踪

每个任务记录需求编号、负责人、预计工时、实际工时、状态、验收人和证据链接。每周一次集成，现场走通主流程，更新问题清单与风险状态。负责人提交可运行成果，由另一名同学依据验收条件检查。

服务器、模型 API 等费用记录实际发生额。演示学员与示例复盘明确标注为演示数据。真实用户试用、长期能力提升和课程评分只根据实际取得的证据填写。

## 五分钟演示顺序

1. 展示演示空间，解释数据来源。
2. 创建独立账号，保存目标和每周时间。
3. 输入真实 CF handle，同步并抽查结果。
4. 生成计划，打开原平台题目。
5. 记录一次参考题解完成及真实用时。
6. 输入时间变化，比较调整前后任务。
7. 接受方案、撤销修改，检查复盘仍存在。
8. 展示需求、进度、风险和验收证据的对应关系。
